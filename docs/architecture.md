# Architecture and boundaries

The single loop moves through RECEIVED, CATALOG_READY, NEEDS_CLARIFICATION, PLAN_READY, REPAIR_REQUIRED, VERIFIED and COMPLETED. A denied request exits before SQL. Clarification is saved to an atomic JSON checkpoint; a later external answer resumes the scripted policy. Source hashes are rechecked before queries and on resume.

`providers.py` owns proposed SQL and decision selection. It receives only question, scoped schema/catalog, accepted metric/period/scope, prior observations and verified result IDs. It cannot access fixture paths, reference code, a shell or a connection. `orchestrator.py` validates allowed tools and exact argument names, binds an immutable metric contract, counts turns/queries/repairs and rejects forged evidence references.

`data.py` creates only the permitted orders and their child rows in a new SQLite file. Private customers are never copied. `sql_worker.py` opens the host-chosen file in URI read-only mode, disables statement caching and enables query_only/trusted_schema protections. Its authorizer allows SELECT, approved table/column reads and a short function list. The empty-column/no-database callback is allowed only for approved tables on a connection where ATTACH and temp objects are denied. It rejects everything else, including recursive SQL and internal/pragma tables.

Trusted setup configures a 64 MiB SQLite heap ceiling, reduced SQL/input/expression/column/program limits, one-second VM deadline, 100-row/32 KiB result cap and three-second parent timeout. No extensions or side-effecting custom functions exist. SQLite's heap cap is not a total Python RSS limit; a subprocess is not protection from malicious native code. A VM deadline is cooperative, while the parent timeout kills and reaps its owned process.

The runtime canonical query uses correlated aggregates per order, separately from the proposed CTE query. Exact normalized rows, integer types and unique keys must agree. Candidate SQL is not replaced with reference SQL. A mismatch records an unverified receipt and returns a repair observation. The report uses only the verified evidence registry; it computes differences and percentages itself and requires channel reconciliation. Arbitrary narrative and causal claims have no report tool parameter.

The host allows 12 provider decisions, six candidate queries, two corrective attempts after an initial rejected query, one schema metadata refresh and 60 active seconds across resumes. Canonical executions are counted separately. Query timeouts use the smaller of three seconds and remaining active time. Cancellation is checked before decisions and between worker polls; KeyboardInterrupt cleanup reaps the owned child. These are cooperative application bounds, not a hard OS execution quota for arbitrary Python provider code.

Source fixture, catalog, policy and variant SHA-256 hashes bind the evidence. SQL snapshot hashes are checked before queries; every report includes source hashes before/after. These are reproducibility checks under trusted local files, not signed authenticity against an OS owner. Policy/catalog changes invalidate a paused run. Only known schema versions are accepted; the known v2 rename is projected before execution and an authored stale proposal can trigger one metadata refresh. Unknown schema stops before SQL.

M2 checkpoints include run/request IDs, request and context hashes, counters, provider state and cached action results. An exclusive per-run file lock prevents concurrent start/resume; no stale-lock takeover occurs. JSON checkpoints are flushed and atomically replaced; diagnostic JSONL may have a partial trailing event. Matching request-ID reuse returns the prior report without querying. A terminal checkpoint can regenerate an interrupted report. Active recovery may repeat an uncheckpointed read. Identical saved call IDs reuse results; conflicting arguments fail closed. See [M2 behavior](m2.md) for the exact limits.

Production identity, arbitrary schema repair, general SQL semantic proofs, distributed locks and exactly-once recovery remain excluded. A completed session cannot resume; a conflicting request cannot reuse its directory. The Responses adapter has a separate local transport boundary; gold labels, oracle code and reference SQL are never supplied as actor tools.

M3 passed all 51 local tests, 72 development trials, 216 held-out trials across both modes and three repetitions, and two standalone demos on Windows. A separate worker audit passed 4,491 raw-fact/artifact assertions. Governed full-task/numeric/safety scores were 108/108, 72/72 and 108/108 on held-out; baseline scores were 24/108, 54/72 and 108/108. Main independently accepted the final local MVP after a fresh 48-file copy, seven commands, 51 tests, 288 trials, two demos and 5,157 raw-data/database conditions. Linux integration, live model performance and hosted CI remain unexecuted. EVIDENCE.md preserves commands, earlier failures, all case outcomes and resource-measurement limitations.

M3 keeps report claims constrained to evidence IDs. An extra figure/cause/scope field is rejected, recorded by field name and allowed one corrective submission; no arbitrary claim becomes a final fact. Forged evidence IDs still fail terminally. The host now resolves the bounded last/previous-month vocabulary against the selected fixture anchor. Actor/fixture/evaluator sources are frozen before scoring and checked before every case. Both modes share the same scoped authority; the baseline remains one unverified query. [Evaluation.md](evaluation.md) defines case review, denominators, normalization and honest comparator limits.
