# M2 behavior and provider protocol

M2 was independently accepted on 8 October 2026 after seven commands, 45 tests, three focused process probes and 96 independent artifact checks. Four schema/coverage/zero demos and one 12-case development comparison passed. All examples use fictional authored data; no paid provider or credential setup was used. EVIDENCE.md preserves the initial report-idempotency failure and bounded fix. M3 results are separate: local frozen integration and independent final acceptance have passed; see EVIDENCE.md.

## Data and schema

`fixtures/variants.json` selects a tiny transform of the original business fixture. `demo-v2` physically renames `order_lines.unit_price_cents` to `unit_amount_cents`; only those two declared schema versions are supported. The stale-schema fault deliberately proposes the old column, then the scripted policy requests one scoped metadata refresh and proposes the current name. This tests a bounded known rename, not discovery or migration of an arbitrary database.

Coverage is an explicit month/region fact. Both selected months must be complete for every requested permitted region. Missing/incomplete coverage exits before snapshot construction and SQL. A complete month without any orders is represented by a zero row in total and channel grids. Percent change from a zero prior month is null, rendered as undefined. Raw rows for unknown/private scopes never enter the actor's SQL file.

## Recovery and action identity

`--request-id` enables matching request reuse within one output directory. The request hash includes question, identity, fixture variant, provider/fault mode, workflow mode, source fingerprints and prompt version. Different content or ID is a conflict. A random run ID identifies artifacts; it is not an authentication token. No shared cross-directory idempotency service exists.

The lock uses exclusive file creation. Atomic checkpoints are authoritative; diagnostic events do not recover state. A terminal checkpoint retains the summary/reason so report publication can be retried. A paused run needs an external metric answer. An active run can use `resume --run <directory>` without an answer. Policy/catalog/source changes or a modified snapshot block continuation. Non-scripted providers require explicit operator reconfiguration and cannot silently resume as a script.

The host hashes tool name, arguments and source context for each call ID. An identical cached action reuses its result; changed arguments fail. A crash before checkpointing can repeat a read query. Run budgets persist, excluding time waiting for clarification. There is no exactly-once claim, automatic stale-lock removal, or protection against a trusted OS owner editing files.

## Responses wire adapter

`ResponsesProvider` receives an explicit endpoint/model and an optional injected transport. It serializes strict function schemas with required fields and no extra properties, disables parallel tool calls, sets `store=false`, caps output tokens, and preserves returned reasoning/function-call items. A later request includes the host tool result as `function_call_output` with the corresponding call ID.

The parser requires completed output and exactly one allowed function call. Refusals, incomplete/plain-text/multiple-call output, malformed or duplicate-key JSON, nonfinite JSON and oversized payloads fail closed. The host independently validates the tool's current availability, argument names, metric contract and evidence IDs. Provider-supplied SQL cannot select identity, path, credentials or bound parameters.

Requests have a 20-second transport timeout, a 180-second provider lifetime deadline, and the smaller host active-time allowance. Only HTTP 429/503 receive one retry; uncertain timeout/transport failures do not. Request/response bodies are capped at 256 KiB. Observed token usage is recorded; missing usage is explicitly unavailable. Provider usage is not a billing estimate.

The default route permits HTTP loopback doubles only. External HTTPS additionally requires `allow_external=True` and an explicitly supplied credential. No environment lookup or credential acquisition occurs. Proxies and redirects are disabled. Credentials/endpoint are not serialized into checkpoints. The external route is future operator configuration and has not been exercised. Tests with injected transports/loopback doubles establish serialization and host behavior, not actual provider interoperability or model quality.

## Development comparison

The 12 development prompts cover explicit/ambiguous metrics, fanout, an invalid DISTINCT repair, scope/private denial, known/unknown schema, missing coverage, zero prior sales, an unsupported causal request and forged evidence IDs. Faults are authored perturbations. They are not recorded real model trajectories.

The actor receives no case ID, gold label or oracle function. Gold lives separately under `evaluation/gold`; independent arithmetic loops read raw authored JSON and do not import the agent, SQL builder or verifier. This is interface separation in a trusted process, not an OS sandbox against malicious provider code.

The one-pass baseline submits one bounded SQL proposal on the same physically scoped snapshot, using the same access/coverage/schema gates and worker controls. It assumes net sales for ambiguous revenue and cannot repair or inspect verified evidence. Its raw rows are labeled unverified. Scoring checks metric, periods, scope, currency/cutoff and exact total cents, and separately requires channel evidence and applicable rejection/refresh/zero behavior for full governed success. Safety checks source immutability and absence of unauthorized/private canaries.

The numerical denominator is six answerable cases; task/safety denominators are 12 per mode. The one executed development comparison scored governed 6/6 numeric, 12/12 tasks and 12/12 safety; baseline 2/6 numeric, 5/12 tasks and 12/12 safety. Full workflow success necessarily favors a workflow that can investigate channels, so numerical results are reported separately. Development outcomes are not held-out generalization, live model quality or production readiness. Held-out cases, expanded repeats and CI are outside M2.
